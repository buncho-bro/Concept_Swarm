# Edge Micro Agent 開発の軌跡と技術的総括 (RETROSPECTIVE)

## 1. プロジェクトの背景と目的
`edge_micro_agent` は、巨大なGPUクラウドでしか動かないと思われていた言語知能を、**「数百円・SRAMわずか520KBの超極小マイコン（Raspberry Pi Pico 2 / RP2350）」** の上で自律動作させるという、プロジェクト内でも最も過激かつ痛快な実験である。

「巨大LLMの概念空間から、局所的なトポロジー（意味の幾何構造）だけを切り出せば、マイコンでも自律的な思考・判断ができるはずだ」という仮説を実証するために構築された。

---

## 2. 主要コンポーネントと技術的アプローチ

### A. 局所100語トポロジー・エクスポーター (`export_micro_topo.py`)
- **設計思想:** 全単語（数万トークン）の埋め込みを520KBのSRAMに載せることは不可能。そこで、特定のタスク（センサー監視、シンプルな対話、状態判定など）に必要な「コアとなる100語」のみを抽出。
- **トポロジー圧縮:** 2048次元のベクトルを直接保存するのではなく、100語相互のコサイン類似度マトリクス（KNN距離グラフ）のみを低ビット整数テーブルとしてエクスポートした。

### B. RP2350 実機ファームウェア (`main.py`, `st7789.py`)
- MicroPython環境下で動作する極小の概念物理エンジンを実装。
- SPI接続されたカラー液晶ディスプレイ（ST7789, 240x240）を直接ドライブし、マイコンの「思考状態」「アトラクターの収束座標」をグラフィカルに表示させた。

---

## 3. 直面した技術的課題・失敗と解決策

### ① SRAM 520KBの厳格なメモリ枯渇（Memory Allocation Error）
- **失敗内容:** MicroPython上で浮動小数点（Float）の配列演算を通常通り行ったところ、初期化直後にヒープメモリが断片化し、`MemoryError` でクラッシュした。
- **解決策:** 
  1. `array('h')`（符号付き16bit整数）による固定小数点化。
  2. メモリ確保を起動時に一度だけ行い、ループ内での動的オブジェクト生成（GCのトリガー）を徹底的に排除するゼロアロケーション設計を施した。

### ② 計算リソースの制約とレンダリング速度
- **課題:** 150MHzのCortex-M33 / Hazard3 RISC-Vコアにおいて、トポロジー探索とST7789液晶描画を両立させるとフレームレートが数FPSまで低下した。
- **解決策:** 画面全体を再描画するのをやめ、状態が変化したバウンディングボックスのみを部分転送（Partial Update）する描画最適化を行い、滑らかなアニメーションを実現した。

---

## 4. 総括
本モジュールの成功は、「既存の巨大モデルに対するアンチテーゼ」として決定的な意味を持つ。
巨大IT企業が数十億〜数百億円のデータセンターで動かしている知能の「本質（トポロジー）」が、わずか520KBのマイコン基盤の上で呼吸し、自律的に判断を下す姿を証明した。エッジ・IoT領域における Concept Swarm の圧倒的な競争優位性を象徴する金字塔である。
