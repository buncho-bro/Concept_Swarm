# Core アーキテクチャ開発の軌跡と技術的総括 (RETROSPECTIVE)

## 1. プロジェクトの背景と目的
`core` は、Antigravity Concept Swarm の根幹をなす **「非言語・潜在空間共有メモリ（Latent Blackboard）」** および **「デュアルストリーム・デコーダー（Dual Stream Decoder）」** を策定・検証した基盤モジュールである。

既存のマルチエージェント（AutoGen, CrewAI等）が抱える最大のボトルネックである「テキストによるシリアライズ・パース（IPC）遅延とGPUトークン浪費」を根本から打破し、**「複数エージェントがテキストを介さず、潜在ベクトル（$D=2048$）を直接共有メモリ上で衝突・合議させる」** という超低遅延アーキテクチャの実現を目指した。

---

## 2. 開発プロセスと主要コンポーネントの変遷

### A. 共有メモリ・ブラックボード (`latent_blackboard.py`, `shared_memory_loader.py`)
- **初期設計:** 通常のプロセス間通信（Sockets / Pipes）を検討したが、10体以上のエージェントが高頻度でベクトルを更新する際のシリアライズオーバーヘッドが課題となった。
- **ブレイクスルー:** OSネイティブの共有メモリ（POSIX shm / Windows Named Shared Memory）を採用。$D=2048$ の Float16/Float32 テンソルを直接メモリスロットにマップし、ポインタ直接参照によるゼロコピー読み書きを確立。これにより合議フェーズのレイテンシをサブミリ秒（< 1ms）へと圧縮した。

### B. デュアルストリーム・デコーダー (`dual_stream_decoder.py`)
- **課題（概念蒸留の罠）:** 潜在空間上でのベクトル合議（引力・反発）を繰り返すと、意味論的純度は高まるものの、自然言語やプログラミング言語としての「文法・トークン配列構造」が崩壊し、デコード時に構文エラーが頻発する現象に直面した。
- **解決策:** デコード処理を2つのストリームに分離。
  1. **Stream 1（概念核）:** 合議によって確定した潜在ベクトル $x^* \in \mathbb{S}^{2047}$。
  2. **Stream 2（語彙・構文アンカー）:** 直近の文脈や専門語彙（`def`, `return`, `class` など）を保持するバイアス項。
  これらをデコード時のLogit Biasとして干渉させることで、概念の正確性と構文の整合性を両立させた。

### C. 10エージェント超並列ベンチマーク (`benchmark_phase3_10agents.py`)
- 10体の専門エージェントを同時稼働させ、共有スロットを介して相互に干渉・合議を行うストレステストを実施。
- 従来のテキストチャット型エージェントであれば数分を要する議論が、わずか数ミリ秒〜数十ミリ秒で収束することを実証した。

## 3. 直面した技術的課題・失敗と解決策

### ① 潜在空間の「引力崩壊（Attractor Collapse）」
- **失敗内容:** エージェント同士が相互に類似度（内積）に基づいてベクトルを引き合う処理を行った際、全エージェントのベクトルが空間内の特定の無意味な中心点（特異点）に吸い込まれ、多様性が失われる現象が発生した。
- **解決策:** 超球面 $\mathbb{S}^{D-1}$ 上での正規化を強制し、直交成分に対する斥力（反発ポテンシャル）を導入。物理学における「荷電粒子の斥力場」を取り入れることで、合議が自明な解に潰れるのを防いだ。

### ② プロセス間同期のデッドロック
- **失敗内容:** Windows環境において、マルチプロセスエージェントが共有メモリスロットを取り合う際、排他ロック（Mutex/Semaphore）の競合によりプロセスが沈黙（Silent Hang）する事象が多発した。
- **解決策:** ロックレス（Lock-free）なアトミック書き込み構造、またはダブルバッファリング方式を導入し、読み取り側が書き込み側を一切ブロックしない設計へと改修した。

---

## 4. 総括と次世代への示唆
`core` で確立された「テキストを捨て、潜在空間で合議する」というパラダイムは、その後の `alice_relay_engine`（数学AIからコードAIへのバトンパス）や `alife_agent_sim`（人工生命エージェント）の全設計へと直接継承された。AI同士の協調において「自然言語は不要であり、人間へのインターフェースとして最後に出力するだけで十分である」という本プロジェクトのコアフィロソフィーを決定づけたモジュールである。
