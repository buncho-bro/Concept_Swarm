# 逆算型目標樹形図エンジン (Goal-Driven Tree Engine / GDTE v3.1) 詳細設計書

## 1. 基本理念と解決する根本問題

### 1.1 従来のAIコーディングの構造的欠陥（「printの罠」と表層的分解）
- **順方向・行き当たりばったり生成:** 多くのAIは「最初から書き始め、次の単語を予測し、エラーが出なければ成功とする」という順方向（Forward）の思考に依存している。
- **無意味な無謬コード（Trivial Bug-Free Code / printの罠）:** 「例外が出ない」ことだけを目的とすると、AIは最小抵抗ルート（空のリストを返す、単に`True`を返す、`print`文を出して終了する）を選び、ユーザーの要件を何一つ満たしていないゴミコードでテストを偽装する。
- **表層的なパーツ分割の限界:** 従来のタスク分割は「コードの部品（x座標、y座標、関数）」といった単なる表面的な内訳に終始し、**「そのプログラムを現実に成立させ、正しく動かすために前提として何が必要か」というシステム的成立要件**を捉えられていなかった。

### 1.2 本システムの解答: 「成立要件・前提依存の逆算因数分解」と「アトミック再帰分解」

システムを正しく機能させ、検証可能にするには、単なる機能コードだけでなく**多角的な前提基盤**が必要です：
1. **コア実行アルゴリズム・探索関数本体**
2. **正しさを保証・立証するテストコードおよび受入検証機構**
3. **計算を支える数学計算ライブラリやデータ構造の基盤（heapq, math, ベクトル演算など）**
4. **それに最適化された実行環境、データ型定義、境界制約**

これらを逆算抽出し、**すべての前提要素が不可分な最小単位（null）に到達するまで掘り下げる**ことで、強固で漏れのない目標樹形図を構築します。

## 2. 🔄 成立要件・前提依存のアトミック再帰分解アルゴリズム

```
>> 『{現在最も遠い所にある要素}』を現実に成立させ、正しく機能・実証するために不可欠な前提要素は何ですか？
   単なる部分品の内訳ではなく、以下のような【成立要件・前提依存】を多角的に含めて可能な限り列挙してください：
   - 1. コア実装・アルゴリズム本体（探索関数など）
   - 2. その正しさを立証・保証するテストコードおよび受入検証機構
   - 3. 支える数学計算ライブラリやデータ構造の基盤（優先度キュー、ヒューリスティック計算など）
   - 4. 実行環境や前提データ型・境界制約・最適化仕様

   もしこれ以上前提や依存を分ける必要のない最小の完結単位である場合は、null とだけ出力してください。
```

※「すべての最終要素が null に到達した時点で Tree 完成」と判定する終了条件はシステム側の制御ロジックで判定します。

### 2.1 4つの多角的視点による成立要件マトリクス

| 成立要件レイヤー | リスト探索プログラムでの例 | A* 最短経路探索での例 | 役割と意義 |
| :--- | :--- | :--- | :--- |
| **① コアロジック** | リスト探索関数本体 | `PathFinder.astar()` メソッド | 要求された機能の直接的実行体 |
| **② 受入検証・テストコード** | リスト探索の受入テストコード | 単体テスト / assert テストシナリオ | 「print逃げ」を防ぎ仕様達成を証明する契約 |
| **③ 数学基盤・ライブラリ** | 計算最適化アルゴリズム、探索インデックス | `heapq` (優先度キュー)、ヒューリスティック関数 | コアを支える下位の計算・データ構造基盤 |
| **④ 実行環境・前提制約** | リスト要素のデータ型、空リスト境界制約 | 2次元グリッド定義、進入不可ノード制約 | 入力不変条件や型安全性の保証 |

## 3. システムアーキテクチャ & モデル分業体制

```mermaid
flowchart TD
    User([ユーザー]) -->|要件入力| Root[1. Root定義: 完成形受入テスト策定]
    
    subgraph DecompLoop [2. 成立要件アトミック再帰分解ループ (Llama-3.1 8B)]
        Root --> FrontierQueue[(未展開ノード探索: 現在最も遠い所)]
        FrontierQueue -->|最深ノードを取り出し| PromptQuery{この要素を成立させる前提は?<br/>コア/テスト/ライブラリ/制約<br/>分解不要なら null}
        
        PromptQuery -->|多角的要件リスト| AddChildren[子ノードを追加: 最大4件]
        AddChildren --> FrontierQueue
        
        PromptQuery -->|null| MarkAtomic[アトミック葉ノードとして確定]
        MarkAtomic --> CompleteCheck{すべての末端が null ?}
        CompleteCheck -->|未完了| FrontierQueue
        CompleteCheck -->|Tree完成!| GoalTree[(完全な目標樹形図 GoalTree)]
    end
    
    GoalTree --> UserApproval{ユーザー承認}
    UserApproval -->|承認!| SwarmExecutor[3. 葉ノード自律攻略スウォーム]
    
    subgraph SwarmExecution [使い捨て作業AI (Qwen2.5-Coder 3B) & 厳格受入サンドボックス]
        SwarmExecutor --> LeafWorker[使い捨て作業AI Ephemeral Worker]
        LeafWorker -->|オンデマンド情報要求| RefBus[レファレンスAI群 / 記憶AI]
        RefBus -->|コード & 忌避制約| LeafWorker
        LeafWorker --> StrictSandbox[厳格受入サンドボックス]
        StrictSandbox -->|assert合格| CommitDAG[正史DAGへマージ & ノード点灯]
        StrictSandbox -->|assert不一致 / print逃げ| FailGrave[失敗墓地へ圧縮 & 斥力登録]
        FailGrave --> LeafWorker
    end
    
    CommitDAG --> RootVerify{Root受入アサーション 100% 通過?}
    RootVerify -->|完全達成!| Deliverable([完成した成果物コードの出力])
```

## 4. 実証実験結果: 『リスト探索プログラムの実装』

メインAIに `llama3.1:8b` を適用し、新プロンプトで実行した実測結果：

### 4.1 生成された樹形図ノード構造
```
- node_0 [ROOT] 『リスト探索プログラムの実装』
  ├─ node_1 [BRANCH] 『リスト探索アルゴリズムの正しさを立証・保証するテストコード』 (② 受入検証)
  │    ├─ node_5 [ATOMIC (null)] 『データ構造（優先度キュー、ヒューリスティック計算など）』
  │    ├─ node_6 [ATOMIC (null)] 『数学計算ライブラリ』
  │    ├─ node_7 [ATOMIC (null)] 『実行環境のデータ型』
  │    └─ node_8 [ATOMIC (null)] 『境界制約』
  ├─ node_2 [ATOMIC (null)] 『優先度キューの数学計算ライブラリ』 (③ 数学基盤)
  ├─ node_3 [ATOMIC (null)] 『リストデータ構造の基盤』 (③ データ構造基盤)
  └─ node_4 [ATOMIC (null)] 『実行環境の前提データ型』 (④ 実行制約)
```

- **立案所要時間:** **25.33 秒**
- **総ノード数:** **9 ノード**
- **すべての末端要素が `null`（不可分アトミック単位）に到達し、Treeが数学的に完成。**

単なる関数定義に留まらず、**テストコード、数学計算ライブラリ、データ構造基盤、前提データ型と境界制約**という多角的な成立要件が自動網羅されています。
