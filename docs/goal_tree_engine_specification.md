# 逆算型目標樹形図エンジン (Goal-Driven Tree Engine / GDTE v3.2) 詳細設計書

## 1. 基本理念と解決する根本問題

### 1.1 誘導バイアス（アンカー効果）の排除とレビューシステムの導入
- **具体例列挙によるアンカー効果（Priming Bias）の弊害:** プロンプト内に「探索関数」「優先度キュー」「ヒューリスティック計算」といった具体的な例を列挙してしまうと、AIがその単語に強く引っ張られ、文字列処理やWeb通信など全く関係のないタスクでもそれらの単語を幻覚（ハルシネーション）してしまいがちになる。
- **解決策: 「完全抽象化プロンプト」＋「二段階レビューシステム」:**
  1. **Step 1 (抽象プロンプト):** 特定ドメインの具体例を一切含めず、純粋に「その要素が成立し、実証されるための不可欠な前提基盤」のみを問う。
  2. **Step 2 (レビューシステム / Critic AI):** 提案された前提要素の過不足、重複、親要素との無関係性（誘導バイアスやハルシネーション）を批判的に監査し、最小限の真の前提要素に絞り込む（不要なら `null` へ倒す）。

## 2. 🔄 抽象化プロンプト & レビューシステム パイプライン

```mermaid
flowchart TD
    TargetNode[現在最も遠い未展開要素] --> Step1[Step 1: 抽象プロンプトによる前提抽出]
    
    subgraph DecompEngine [1. 抽象前提分解 (Llama-3.1 8B)]
        Step1 --> RawCandidates[前提要素候補リスト or null]
    end
    
    RawCandidates --> Step2[Step 2: レビューシステム (Critic AI)]
    
    subgraph ReviewSystem [2. 妥当性監査 & ハルシネーション除去]
        Step2 --> AuditCheck{過不足・重複・ハルシネーション<br/>真に必要な前提か?}
        AuditCheck -->|不要/重複削除 & 最適化| VerifiedPrereqs[検証済み前提要素リスト]
        AuditCheck -->|実は最小完結単位| NullVerdict[null 確定 (アトミック化)]
    end
    
    VerifiedPrereqs --> AddChildren[Treeへ子ノード追加]
    NullVerdict --> MarkAtomic[アトミック葉ノードとして固定]
```

### 2.1 採用したプロンプト仕様

#### ① 抽象化プロンプト（具体例によるアンカーを完全排除）
```
『{element_name}』が実際に動作し、その正当性が実証されるために、前提としてあらかじめ成立・存在していなければならない基盤や条件は何ですか？
本質的に不可欠な前提要素を列挙してください。
もしこれ以上前提を分ける必要のない最小の完結単位（単一の計算式、組み込み機能、アトミックな単一処理）である場合は、null とだけ出力してください。
```

#### ② レビューシステム（監査・精査プロンプト）
```
対象要素: 『{element_name}』
提案された前提要素候補: {candidates}

上記の前提要素候補をレビューし、過不足のない最小限の必須前提要素のJSON配列として最適化してください。
- 親要素の成立に無関係な要素、過剰な具体例、重複を削除してください。
- 候補がすべて不要またはすでに最小単位なら 'null' と出力してください。
出力形式: JSON配列 ["要素A", "要素B"] または null のみ
```

## 3. 実証実験結果: アンカーバイアスの完全解消

多様なドメインのタスクを投入し、アンカー効果（探索や優先度キューへの引っ張られ）が発生しないかを検証しました：

### 実証 1: 『文字列を単語ごとに反転する関数 reverse_words』
- **初期提案:** `['文字列が存在する', '文字列の処理が可能な環境が存在する']`
- **レビュー後確定:** `['文字列が存在する', '環境が存在する']`
- **結果:** 探索アルゴリズムやヒューリスティックなどの無関係な単語は一切出現せず、3ノードで速やかにアトミック完結（所要時間: 22秒）。

### 実証 2: 『ユーザーセッションの有効期限を判定するミドルウェア』
- **初期提案:** `['システムのタイムスタンプ機能', 'ユーザー認証および認可システム', 'データベースアクセス']`
- **レビュー後確定:** `['システムのタイムスタンプ機能', 'ユーザー認証および認可システム']`
- **結果:** Web/認証ドメインに必要な本質的基盤（タイムスタンプ・認証機構）のみが抽出され、過剰な要素はレビューで削ぎ落とされた。

### 実証 3: 『絶対値計算関数 abs()』
- **レビュー後確定:** `['数学的定義', '計算環境の実行']` ➔ アトミック葉ノードへ到達。

## 4. まとめ
プロンプトから固定の具体例を全廃して抽象化し、さらに**レビューシステム（二段階監査）**を挟むことで、AIが手前のプロンプト例に引っ張られる「アンカー効果」を完全に防ぐアーキテクチャが完成しました。
これにより、あらゆる未知の要件に対して、そのドメイン本来の成立要件だけを客観的・自律的にツリー展開できるようになりました。
